# SAI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans inline. The owner preapproved work; no repeated design/plan approval is needed.

**Goal:** A runnable relationship/care pilot with durable state, CLI conversation and host-hook adapters.

**Architecture:** Python standard-library engine, SQLite store, thin CLI, contextual hook output, optional installed CLI model backends. Native host trust is never modified.

**Tech Stack:** Python >=3.11, sqlite3, argparse, subprocess, unittest, setuptools packaging.

**Spec:** `docs/superpowers/specs/2026-11-19-sai-design.md`

## Global Constraints
- No runtime dependencies; Korean-first; Windows runtime verification, cross-platform source.
- No global settings/trust modifications, private data commits, silently simulated model successes, or copied competitor assets.
- State persists independently of process, workspace and model. Mode off preserves data and suppresses persona.
- Meaningful negative emotions require a cause. Mood and affection remain separate.

## Review Focus
- Unicode, malformed/oversized input and shell metacharacters: validate, preserve data, never execute user text.
- Concurrent CLI/hooks and duplicate events: transactions prevent lost updates; known event IDs are idempotent.
- Existing/unknown SQLite schema and inactive mode: do not silently reset or reactivate.
- Failed model call or malformed intent: show failure, no fake response or fabricated memory.
- Hooks after compaction/off/new project: reload stored state, clear persona when off, never weaken host policy.
